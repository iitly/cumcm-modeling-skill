# 数据、逐问证据与独立复核

最后更新：2026-11-16（北京）。方法取舍与来源见 `references/cumcm-agents-adoption.md`。本文件是 `math-modeling-paper` 的补充，不是第二套阶段系统；沿用用户现有目录与最新决策。

## 1. 题意台账：先区分题给条件和自加假设

步骤 1 读完题面、图和附件后，为每个实际小问列下表。沿用已有 `task_split`、题意对齐表或决策日志，不为同一事实再建一套账。

| 要求 ID | 原始出处 | 条件性质 | 输入与单位 | 必须交出的结果 | 公式/代码位置 | 验收证据 |
|---|---|---|---|---|---|---|
| Qn-Rk | 文件名 + PDF 页/图号，或工作表 + 单元格/字段 | 题给硬约束 / 题给目标 / 推导条件 / 自加假设 / 歧义待定 | 实际字段、对象、单位、前问结果 ID | 数值/方案/区间/解释等，按题面写 | 完成后回填 | 检验方法、实际输出位置与状态 |

- 业务常识推导出的“隐藏约束”先标为推导条件或假设，并给依据；不能改写成题目明示要求。歧义影响主结论时，列可行口径和区分证据，必要时做定量对照。
- 各问可以共享变量、承接结果。把真实依赖写成输入输出接口；没有依赖的问不硬写承接句。
- 模型选择说明至少落到：本题对象是什么、变量/参数代表什么、为什么适用、用什么数据、如何检验。直接复用步骤 3–4 的内容，不额外生成一份套话指南。
- **完成判据**：每一条题给硬约束和必答输出都有原始定位；尚未实现的行明确为未完成，不能用“报告已写完”代替实现证据。

## 2. 数据体检与清洗：保留原值、保留处理理由

步骤 1 做只读体检，求解前执行必要清洗。数据本来可用时记录“无需变更”及检查依据，直接复用，不为走流程制造清洗。

### 2.1 先体检，再选处理

逐文件、逐工作表/字段统计：有效数据区与表头、行列数、类型、主键/重复键、缺失及哨兵值、数值范围、单位、时间顺序、采样间隔、实体分组和关联关系。文件打不开或字段含义存疑，标为未读/待确认；不能声称已完整读取。

原题和原始附件只读。输出写现有独立目录；没有约定时可用 `数据预处理/clean/`，模型专用变换另存或放入可复跑 pipeline。正式输入记录内容指纹，复跑后核对原件未变。清洗后的数据不自动成为唯一真相；必要时回到原始观测复核。

### 2.2 每项变更留账

记录：来源文件/表/字段/稳定行标识 → 问题与数量 → 处理方法及理由 → 影响数量 → 输出位置。每种实际处理至少抽查有代表性的前后样本和边界点；样本数由变更规模与风险决定，不固定抽几行。

- 重复值先判断是否真重复。同一人的重复测量、同一设备不同时间观测等不能按整行或局部特征相同自动删除。
- 缺失要区分未知、零、未测、结构性不适用。中位数填充、插值、删行/删列均需本题依据，不设固定比例自动处理；证据不足时保留缺失标记或比较不同口径。
- IQR、箱线等仅作异常候选标记；合理极值保留。修正疑似错误需可核实的单位、定义域或原始记录依据；影响主结论的删改纳入稳健性核验。
- 单位纠正与格式清理可以在基础清洗中做，但记录换算关系。**基础清洗与模型缩放分开**：后者待模型确定，再判断是否需要标准化、归一化、正向化等，并保存实际拟合参数；不照搬“所有数据一律归一化”或“优化题一律不得缩放”。
- 预测/分类任务先按时间、实体或题意定义训练/验证/测试边界。插补器、缩放器、特征选择等从数据学习的参数只在训练侧拟合；调参只用验证侧，最终测试集不参与选择。时序插值不得偷看该预测时点尚不可用的未来值，实体重复观测不得无理由跨集合泄漏。

### 2.3 清洗验收

1. 原件内容指纹不变；清洗脚本在授权工作区实际运行，保留命令、返回码与日志。
2. 前后行数、缺失数、极值、数据类型和键关系逐项对账。删行、保留缺失、改变范围都可以有正当理由，关键是变更数量与记录闭合；不用“行数不能减/极值必须相同”一刀切。
3. 关键单位/总量/平衡关系按题型检查；变换后的量和阈值使用同一口径，输出必要时正确逆变换。
4. 从原件重新生成，不叠加清洗上次输出；随机处理记录种子和依赖版本。
5. 有未解释的差异时不得进入依赖该数据的正式求解；独立无关的小问可继续。

## 3. 每问最小证据包：让别人不靠聊天记录也能复核

步骤 5 每问完成后整理以下内容，沿用已有结果表、日志和 `decision_log.json`。缺什么补什么，不强制搬目录或复制数据。

| 内容 | 必需信息 | 完成判据 |
|---|---|---|
| 题意与模型版本 | 要求 ID、采用的模型、约束/假设、与前问接口、最新选型决定 | 每个必答输出都有对应实现与检验 |
| 运行凭据 | 实际运行命令、解释器/关键依赖版本、输入及源码/配置指纹、参数、随机种子、返回码、日志位置、运行 ID | 凭据来自真实执行；退出 0 还要核对内部断言和产物 |
| 核心结果 | 数值/方案、指标定义与方向、单位、适用样本/情景、有效数字、来源定位 | 可从指定产物复算，不依赖手抄聊天数字 |
| 模型参数 | 参数/权重/系数、实际值、单位、来源或标定方法、数据划分 | 区分题给常数、估计值和算法超参 |
| 验证与风险 | 可行性/守恒/量纲/特例/留出/收敛等实际检查、范围、失败项和局限 | 区分已验证、未验证、不适用；误差或区间有计算依据 |
| 图表索引 | 文件、输入结果、绘图脚本、图所支持的结论及正文位置 | 自动导出、能复现；数量服从证据需求 |

用户偏好 Excel 时，默认把核心结果、模型参数放同一工作簿的两个命名工作表；有多表/大规模/非表格结果时沿用适合的 CSV/JSON/NPZ 等，再提供索引，不强迫所有内容塞进 Excel。不要覆盖题目指定的结果模板。审查记录骨架见 `templates/subproblem-review.md`。

### 3.1 数字的单一来源

- 论文的计算结果和摘要数字从已确认的该次运行产物取；题给常数从题面定位；文献数值从用户提供并核实的原文取。写明表/字段/单元格或数组索引；计算得到的比率、倍数也要可复算。
- 文稿可按统一有效数字舍入，不要求显示字符串逐字相同；同时留存未舍入值、单位和绝对/相对容差。改变单位要注明换算，不以改数字迁就排版。
- 数据/源码/配置内容指纹与运行 ID 一起绑定；跨表/数组比较先核完整身份键（如实体、时间、情景、小问/折次），拒绝重复键、错位、漏行和非有限值，不能只核行数或排序后的数值相同。把容差用于匹配身份后的误差，不用容差掩盖错对象。
- 数据、清洗规则、公式、约束、参数、代码或所用前问结果变化后，标记受影响的结果、图、正文、摘要和裁决为待重验；只重跑受影响依赖链。纯文字/版式变动只重新检查相关文档项。
- 已封版时只读登记缺口；所有重跑、编译和回填仍受主 skill 的副本授权门约束。

## 4. 复核：独立的是证据与检查，不是角色称呼

### 4.1 何时升级

日常先执行本技能的自检。关键读题歧义、高影响数据变换、核心公式/约束、高风险求解结果和提交前，若额外复核能改变决策，再使用独立上下文或已获授权的专家通道。只改措辞、修普通报错不强制叫第二个 AI。

角色按当前项目分工和真实通道确定：Hermes 是平台，不能据此推定底层模型、模型提供方或“裁判天然更可靠”。实际用了哪个模型就如实记录，不确定写未知；不为获得“独立”标签擅自改配置、开付费服务或委派。

### 4.2 复核者自己读取原证据

按顺序读取：原题对应条款和原始数据 → 当前模型/决策与数据账 → 实际源码/配置 → 真实结果与日志 → 生成方的自检。不要只凭报告审报告；参与设计报告的同一上下文不能独立验证自己的读题。

复核分三层，逐层注明范围：
1. **题意/对象层**：原始场景、拓扑、参考方向、数据划分和输出目标是否读对。
2. **建模/实现层**：方程、约束、量纲、假设与代码是否对应；不把有缺陷的选型报告当不可更改的命令。确需换模型时，先给证据、修改决策并更新依赖项。
3. **求解/结论层**：用手算尺度、解析特例、小规模精确解、不同实现/求解器或直接读取原件的独立脚本复算关键数字。重跑同一个求解器只能证明可复现；错误方程也可能通过代回。

复核者在独立临时输出区运行，先查脚本写入范围，不覆盖选手结果。不能执行或未拿到原证据时写“未完成该层验证”，不以语言审查充当数值复核。同模型不同上下文可减少共享上下文影响，但不证明错误相互独立；没有独立通道就如实标自检，不能宣称完成双智能体审查。

### 4.3 裁决与有限返修

每条意见写：严重性 → 文件和精确位置 → 观察到的现象 → 证据/复算 → 原因（证实或待定）→ 最小修正 → 通过条件。对意见逐条采纳、反驳或待核，并保留依据；不盲从“裁判”。

状态只用：
- **通过**：本次明确列出的检查已通过，关键数值有真实复算；注明未覆盖的部分，不代表保证获奖。
- **退回**：证据已确认存在错误/遗漏，指明受影响范围。
- **待核**：关键证据、环境或独立复算不足；不能当作通过。

同一关键问题的专家往返默认至多两轮，遵守用户协作规则；代码故障的停止与换路条件只按主流程执行，项目另有明确预算时优先遵守，不能重启进程重置预算。未收敛就列最小未决项、影响、替代路线与人工决策点，不无限“审到通过”。阻断主答案的未决项不能靠轮次用完自动放行。

## 5. 模板母本与工作稿分离

模板库/安装目录只读，复制所需文件到用户项目的论文工作区后写作；已有有效工作稿不重建、不搬家。引用图、附录代码直接指向本次确认的产物，复制进提交包后核对字节和相对路径。

主源选择、Word/OMML 与 LaTeX 导出统一按 `references/writing-delivery.md` §6。已有有效 DOCX 主稿就继续编辑该稿，不因旧记录提过 Markdown 而重新生成并覆盖；模板母本和冻结件只读。

## 6. 行为验收场景

以下是维护时的检查用例，不是已运行的竞赛实验：

| 输入情景 | 应有行为 |
|---|---|
| 用户说“看看/改良 skill”，未给赛题 | 只维护 skill，不问奖级、不建比赛项目 |
| 附件没有缺失和异常 | 体检并记录无需变更，不强行清洗或归一化 |
| 时序预测数据有缺失 | 按可用时点和划分边界处理，不用未来值插补过去预测特征 |
| 同一对象重复测量 | 先确认观测层级，不自动去重；划分时检查实体泄漏 |
| 某问两张图足够 | 以证据覆盖验收，不为凑张数添图 |
| 独立通道不可用 | 标自检/待核，不假称独立审查通过 |
| 前问结果改了，后问依赖它 | 标受影响结果和文稿待重验，保留无关小问 |
| 用户已封版又问评估 | 只读原提交件；不跑会写盘的求解器或编译器 |
